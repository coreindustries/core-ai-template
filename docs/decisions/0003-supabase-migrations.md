# ADR-0003: Database Migrations via Supabase CLI (Default)

- **Status**: Accepted
- **Date**: 2026-04-21
- **Deciders**: Platform engineering
- **Supersedes**: —
- **Related**: `.claude/rules/database-migrations.md`, ADR-0001 (secrets hygiene)

## Context

Projects created from this template default to Postgres for relational data and RLS (Row-Level Security) for tenant isolation. The practical path to a well-structured Postgres + RLS setup with a first-class local dev loop, preview branches per PR, and a migration CLI that plays well with GitHub Actions is **Supabase**.

The alternatives we evaluated:

| Option | Local dev | Preview envs | Migration CLI | RLS ergonomics | Cost |
|---|---|---|---|---|---|
| **Supabase** | `supabase start` → full stack | Native preview branches | `supabase migration new/push/reset` | First-class (built around RLS) | Free tier generous; Pro at scale |
| Raw RDS + `golang-migrate` | Docker compose postgres | Manual (Terraform) | Solid, simple | Have to wire yourself | RDS + ops |
| Prisma Migrate | `prisma dev` | Manual | Solid | Not RLS-aware out of box | DB provider + ops |
| Drizzle + drizzle-kit | Docker compose | Manual | Good | Not RLS-aware | DB provider + ops |
| Neon | Docker compose | Branch per PR | Via external tool | Wire yourself | Paid at scale |

Supabase wins on the two high-leverage axes: **preview branches per PR** (huge for review quality) and **RLS-native conventions** (huge for correctness when the app is multi-tenant). The CLI is a thin wrapper around standard Postgres migration semantics, so switching away later is straightforward — the migration files are just numbered `.sql` files.

## Decision

Default migration platform: **Supabase CLI**.

- Schema changes ship as `supabase/migrations/YYYYMMDDHHMMSS_<name>.sql`, generated by `supabase migration new`.
- Local dev uses `supabase start` + `supabase db reset`.
- CI uses `supabase db push --db-url "$DB_URL"` on merge.
- Preview branches are enabled on all Supabase projects created via this template.
- Secrets (DB URL) flow via chamber — never paste connection strings.
- RLS is mandatory on user-data tables; CI gates missing RLS.

Projects with constraints incompatible with Supabase (on-prem-only, non-Postgres, regulatory) override this in `prd/00_technology.md` and adjust the Makefile; the invariants in `.claude/rules/database-migrations.md` (numbered files, no editing committed migrations, expand/contract, CI fresh-DB apply) still apply.

## Consequences

**Positive:**

- One canonical dev loop: `supabase start → supabase migration new → supabase db reset`.
- Preview Postgres per PR makes reviews 10× more honest — reviewers can actually hit the schema.
- RLS conventions baked into the tooling; less-experienced engineers ship safer tables.
- `supabase gen types` means type safety against the real schema, regenerated each migration.
- pgTAP-based RLS tests are the right size for agent-written tests.

**Negative:**

- Supabase vendor surface: the CLI, the hosted platform, the Docker images. Migration files are portable; everything else isn't.
- Running `supabase start` locally requires Docker; not ideal for very thin dev environments.
- Preview branches cost (included in Pro tier). Free-tier projects can disable them and fall back to ephemeral cloud Postgres in CI.

**Neutral:**

- Migration semantics are standard Postgres — knowledge transfers.
- Moving off Supabase later: point `psql` at the new DB, apply the same `.sql` files in order. The migration state table (`supabase_migrations.schema_migrations`) is portable.

## Alternatives considered

- **Prisma Migrate**: strong TypeScript ergonomics, weaker RLS story. Would require ORM-level access-control code that Supabase lets us push into RLS.
- **Drizzle + drizzle-kit**: lean, type-safe, but no preview-branch story; we'd be assembling it.
- **Raw migrations (golang-migrate / Flyway)**: works, no vendor lock-in, but loses the preview-branch leverage and the RLS-first posture.
- **No migrations — schema-as-code**: rejected. Incompatible with zero-downtime deploys and expand/contract.
